# Changelog

All notable user-visible changes to this project are documented here, newest first.
This log follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Behavior changes under `src/` add an entry under `[Unreleased]`; internal refactors and docs-only commits are exempt.

## [Unreleased]

### Added
- A download that stalls is now recovered instead of hanging. The watchdog (`dev.cljtoc.supervision.watchdog`) is a child of the download supervisor: it watches the blocks a download receives and the peers it is connected to, and when that progress stops for longer than fifteen seconds it fires. Firing crashes the coordinator subtree, so the download supervisor restarts it while its restart budget holds; a download that never moves runs out of budget and fails with `:restart-budget-exhausted` instead of waiting forever for blocks that never arrive. Closes `torrent-client-clj-0c9.11`.
- Peer connections are now supervised one-for-one (`dev.cljtoc.supervision.peer-supervisor`). The peer supervisor owns the peer workers of a download and the event channel they write to, so a peer worker that crashes on an unexpected failure is restarted on its own instead of taking the download with it: the other peers keep running and the download carries on. A peer that keeps crashing is dropped once its per-connection budget runs out (three restarts a minute by default), so a flapping peer cannot spin the supervisor forever; the peer that is dropped leaves the swarm and the download fails with `:no-peers` instead of hanging. A peer that disconnects cleanly is not restarted: the peer is gone and the swarm moves on. Closes `torrent-client-clj-3ea`.
- A multi-torrent session is now owned by a session supervisor (`dev.cljtoc.supervision.session-supervisor`), which starts one download-supervisor subtree per torrent and restarts only the child that crashed. One flaky torrent no longer takes every torrent with it: a restarted download comes back while its siblings keep running. A download whose coordinator crashes is restarted while a sliding-window budget holds (three restarts a minute by default) and resumes from the pieces it already verified instead of re-fetching them; when the budget runs out the download fails with `:restart-budget-exhausted` instead of being restarted forever. `torrent.resume` runs the same way. Closes `torrent-client-clj-0c9.13`.
- A session can own several downloads in one process (`dev.cljtoc.orchestration.session`). `torrent.download` now takes one or more torrent paths and starts them together: a path that fails to start is reported and the rest still run; a torrent whose tracker announce fails is kept as a `:failed` download and saved, so `torrent.resume` can retry it; two torrents that declare the same output path are refused as `:overlapping-output` instead of overwriting each other's verified bytes; each download runs on its own thread, its terminal record is saved as it finishes rather than behind a stalled sibling, and an ordinary crash in one leaves the others' final records intact; the started records are saved before the blocking run so a crash mid-download leaves resumable state. Two paths whose torrents share a basename derive the same id, so the later one is reported as a `:duplicate-id` failure instead of silently replacing the first. The command exits `1` when any torrent failed to start or ended `:failed`. A state save that fails mid-run is reported once every download has finished and also exits `1`, instead of exiting from the worker thread and abandoning its siblings. `torrent.status` with no id now lists every saved download (most recent first) instead of only the most recent, so the torrents a session started both appear; a named id still shows that one. `torrent.status` skips a state file that decodes to valid EDN of the wrong shape (an empty map, a bare number) instead of throwing on it. The JVM now shuts down its agent pool after a command succeeds, so the CLI exits immediately instead of lingering ~60 seconds. The session lives for a single blocking command — querying a running session, pausing it, and removing the blocking CLI are the daemon's job (`torrent-client-clj-0c9.12`). Closes `torrent-client-clj-0c9.6`.
- Client settings file (`~/.config/cljtoc/config.edn`, overridable with `--config <path>` anywhere in the command): dirs (`:state-dir`, `:piece-cache-dir`, `:output-dir`), the announce port (`:peer-port`, Transmission's 51413), and the per-torrent peer cap (`:max-peers`) now load from disk instead of living as literals. Knobs the manager reserves but does not enforce stay out of the file rather than being offered as settings that do nothing. The file is the single source for these values: `torrent.download` no longer takes a positional output dir, so destinations cannot be set two ways. Directory values must be absolute: a relative one is refused rather than resolved against the working directory, so a config cannot download somewhere different under `lein run` than under the jar. A missing file means defaults; a corrupt one stops the command with the parse reason. `--config <path>`, accepted anywhere in the command line, only selects which file to read. Defaults follow Transmission: the download dir honors XDG_DOWNLOAD_DIR from user-dirs.dirs and otherwise falls back to `<home>/Downloads` (correct on macOS and Windows), resume state lives in `<config home>/cljtoc/state`, and the piece cache in its own `<cache home>/cljtoc/pieces` folder. Closes `torrent-client-clj-0c9.1`.
- A new `IRandomnessPort` injection seam replaces the direct `java.security.SecureRandom` use that previously generated peer-ids in both tracker announces (`ports/network_impl.clj`) and handshake peer-ids (`orchestration/download.clj`). Real ports (`SecureRandomRandomness`) and test doubles (`MockRandomness`) are interchangeable via `network-impl/create`'s `:randomness-port` opt; absent means a fresh `SecureRandomRandomness` is constructed. A pure `dev.cljtoc.domain.backoff` module owns the jitter math (`exponential-backoff`, `with-jitter`, `schedule`) that the supervision layer (issue #28) and re-announce (#22) and watchdog (#23) will share. Per ADR-0011; closes #29.

### Fixed
- `torrent.status <id>` now ignores a state file whose record names a different download, instead of showing that other torrent's progress. A record filed under the wrong name is treated as corrupt, so a named lookup cannot act on the wrong torrent.
- `XDG_DOWNLOAD_DIR` parsing in `user-dirs.dirs` now resolves `\"`, `\\`, and `\$` escapes without evaluating shell syntax, and expands only a leading unescaped `$HOME`. Previously every quote was stripped and every `$HOME` replaced, so a directory such as `$HOME/Price$Lists` kept its backslash and downloads landed in the wrong folder.
- The state lookup behind `torrent.resume`, `torrent.pause`, and `torrent.status` now applies the torrent-path fallback only to arguments that look like torrent paths (a `.torrent` suffix or a path separator). Previously a missing dotted id such as `archive.v2` fell back to `id-from-path` and resolved to the saved state for `archive`, so `torrent.stop archive.v2` could delete the wrong download. A bare id that matches nothing now reads as not-found.
- `evict-piece-cache` now checks every `File/delete` result and returns `:evict-error` naming the surviving entries when any deletion fails, instead of reporting `:evicted` while the bytes stay on disk. The completion warning path in `evict-completed-cache` now actually runs on such failures.
- A completed download now evicts its own piece-cache entries (`IDiskPort/evict-piece-cache`). Every finished download previously left `piece-cache-dir/<scope>/piece-*.dat` behind permanently — roughly one torrent-size each, unbounded across runs — because completion performed no disk I/O and nothing ever removed the cache. Eviction runs at both completion sites (event loop and `run-download`'s fast path), removes only the completing download's content-scoped directory, leaves the output layout byte-identical, and never touches entries of downloads that did not complete. A failed eviction logs and does not fail the download. Eviction leaves the output files unchanged. Closes `torrent-client-clj-0c9.23`.
- `torrent.resume`, `torrent.pause`, and `torrent.status` now accept a torrent path as well as a bare download id. They previously used the argument verbatim as a state id, so `torrent.resume ./tmp/foo.torrent` printed "No paused download found" even though the record existed under `foo`. The shared lookup tries the exact id first, then the id derived from the path, so a bare id carrying dots (`archive.v2`) still resolves exactly. Closes `torrent-client-clj-0c9.21`.
- `assemble-piece` now returns an error envelope for malformed blocks instead of throwing: a block with no byte array returned an NPE, a non-byte `:data` a `ClassCastException`, and a block running past the piece end an `ArrayIndexOutOfBoundsException` from `arraycopy`. Because the coordinator loop that calls it is not a supervised worker, a malicious peer could kill a download with an over-long block. Blocks are now shape- and bounds-checked up front (`:invalid-block`, `:block-overflow`), so the function is total over its declared spec and joins the generative fdef pin. Closes `torrent-client-clj-0c9.26`.
- Removed the eager `clojure.test.check.generators` require from `coordinator.clj` that prevented the namespace from loading in the packaged uberjar (test.check is `:dev`-only). Both custom `with-gen` generators now use `gen/fmap` over `gen/tuple` from `clojure.spec.gen.alpha`, which loads test.check lazily at generation time.
- Split `::addressed-event` into a permissive `::addressed-event` (address-only, for `on-disconnected`'s refused-dial events) and a strict `::connection-event` (requires `:peer-state`, for `on-connected`). Previously the shared spec rejected valid address-only disconnect events under instrumentation.
- Tightened the `::coordinator-state` spec so the generative fdef check can no longer produce non-Associative values at peer-address keys (previously a shrunk counterexample `{:active-peers {false 0}}` crashed `requeue-assignment` with `ClassCastException: Long cannot be cast to Associative`). `::active-peers` now requires map values at peer-address keys (`s/map-of any? ::active-peer-info`), `::active-peer-info` uses `:opt-un` to accept the partial maps `assoc-in` creates, and both `::active-peer-info` and `::addressed-event` carry custom `with-gen` bypasses around spec.alpha 0.5.238/0.6.249's `s/keys` gen-consumption bug. `::peer-state` in `peer_state.clj` gets a constructor-backed `with-gen` because its `BitSet` field has no default generator. Bumped `org.clojure/spec.alpha` from 0.5.238 to 0.6.249.
- UDP tracker responses are now checked against the live request: `parse-udp-connect-response` and `parse-udp-announce-response` take an optional `{:action :transaction-id}` expectation and refuse mismatches as `:action-mismatch` / `:txn-mismatch`, so a stray or duplicate datagram fails the announce attempt instead of connecting to a stranger’s connection id or returning a stranger’s peers. `try-udp-tracker` threads both expectations through and surfaces refused builds as typed step errors instead of an NPE-masked `:udp-failed`.
- UDP tracker announces no longer fail when the request carries no event: the `::event` spec listed `nil` inside a set predicate, which never matches `nil`, so an event-less announce was rejected and surfaced as an inscrutable NPE-masked `:udp-failed` instead of announcing with event 0 (none) as the builder already encodes. A loopback integration test now drives connect plus announce through the real port code against a local double and asserts the returned peer.
- UDP tracker announces now survive a lost or strayed reply instead of failing the whole announce: each connect and announce step re-sends with BEP 15 exponential backoff, a fresh transaction id per attempt, and first success wins. Each attempt sends once and then keeps receiving until its wait runs out, discarding stray replies (a late duplicate's transaction id can never match the live attempt) instead of burning a retry on each one; refused builds and dead sockets fail fast. Backoff starts at `:udp-retry-base-delay-ms` (15000 ms by default, doubling per attempt) and stops after `:udp-max-attempts` (3 by default) with a step error naming the attempts. Both steps share one overall `:udp-tracker-budget-ms` (60000 ms by default, about one step's worst case under default knobs): socket waits and backoff sleeps are each capped to what remains, so one dead tracker — or six dead fallbacks in sequence — cannot stall an announce call past its budget. A loopback double that drops datagrams proves the recovery, one that answers out of order proves same-attempt recovery, and a silent tracker proves exhaustion stays bounded.
- Prepared per-piece writes (`write-prepared-piece`) now re-validate live on every piece through a parent-directory mtime gate, refusing a post-prepare alias that points an untouched declared path at a touched file (e.g. a symlink or hard link created after `prepare-output-layout`). Previously, an untouched path newly aliased onto a touched target slipped through because the untouched snapshot was never re-scanned. When no parent dir changed since prepare, only the touched files are re-resolved (one stat per distinct parent plus O(touched) work — flat in file count); when a parent changed, the whole layout is re-resolved and the full alias check runs. Measured probe (1024-byte files, initialized layout, unmutated tree): per-piece prepared-write cost flat at ~0.6ms at 50/200/1000 files.
- An explicit `--config <path>` that does not exist now stops the command with `Config file not found: <path>` instead of silently running on defaults. Only an absent file at the default location still means defaults, so a mistyped path cannot look like an empty config.
