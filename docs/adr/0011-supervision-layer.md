# Crash-only supervision as an explicit layer

The crash-only supervision principle from the constitution gets its own layer with two namespaces: `dev.cljtoc.supervision.peer-supervisor` (one-for-one, owns peer workers and the per-connection restart budget) and `dev.cljtoc.supervision.download-supervisor` (rest-for-one, owns the coordinator and its sibling children — re-announcer for #22, watchdog for #23). Both live inside one CLI invocation; cross-invocation recovery still goes through `torrent.resume` and the existing persistence seam. `retry-download` and `can-retry?` are deleted (were unreachable from `src/`; user-driven restart is now expressible as `pause-download` → `torrent.resume`, which the persistence seam wires through `run-download`). Randomness moves to a primitive `IRandomnessPort` consumed by a pure `domain.backoff` module that all three supervisor slices share. SIGINT triggers a clean shutdown: peer connections close, in-progress state persists, then the JVM exits cleanly.

## Considered Options

- **Single supervisor at the download level**: rejected — a flaky peer should not restart the whole coordinator. Rest-for-one at the download level solves it but forces every peer concern through rest-for-one, conflating grain.
- **Per-address restart budget**: rejected — conflated identity with location. The same `host:port` could be a transient network blip today and a dead host tomorrow; per-connection budget treats each handshake attempt independently.
- **Keep `retry-download` as an outer download-level backstop**: rejected — it had no callers in `src/`, and the user-driven restart is expressible through the resume-and-run path that the persistence seam already wires.
- **Persistent supervisor across CLI invocations (daemon mode)**: rejected — requires the supervisor's intensity counters and child specs to be persisted, duplicating the Download-record persistence seam. The CLI blocking shape is preserved instead.
- **Shaped randomness port (`(jitter-ms base cap)`)**: rejected — couples the port to a time-domain concept that already has a pure home in `domain.backoff`. Ports stay primitive; the pure module owns jitter math and is shared by peer restart, re-announce, and watchdog.
- **`alt!!` on a merged done-chan (no per-worker identity)**: rejected — the restart decision needs to know which address just exited. `async/merge` discards that without extra plumbing.
- **Per-worker timer for the restart budget window**: rejected — one supervisor-wide prune timer that runs every `T/4` seconds gives approximately-correct budget accounting with far less bookkeeping.
- **Crashes don't count against the per-connection budget**: rejected — a buggy peer crashing `N times` in `T` seconds should still be droppable. Crashes and clean exits share the same budget treatment, distinguished only by log level.
- **Inline supervision inside `run-download`**: rejected — the constitution names supervision as its own layer above coordination. Two new namespaces make the layer boundary explicit and keep the orchestration layer focused on lifecycle states.

## Consequences

- **Layer diagram gains a top tier.** The current four-layer diagram in `doc/architecture.md` already names "Supervisor Layer → lifecycle management, restart policies" but no namespace implements it; this ADR materialises that layer with two concrete namespaces. The pre-existing inconsistency between the diagram (four layers) and the table (six rows including Orchestration and Ports) stays — the diagram still describes the dependency direction, the table still lists every namespace family. Worth a separate cleanup.
- **`run-download` shrinks but doesn't change shape.** It still blocks until completion; the supervision logic moves out into the two new namespaces. The CLI commands `torrent.download` and `torrent.resume` need no changes.
- **Channel ownership changes.** `events-ch` is now owned by the peer supervisor, which passes a write-end to each worker and a read-end to the download supervisor (which forwards it to the coordinator). The peer supervisor closes `events-ch` when the running-worker count reaches zero *and* no restart is scheduled; the download supervisor observes that close as the coordinator's exit signal.
- **`retry-download` and `can-retry?` are deleted.** The `:error :retry-count` field is removed from any persisted state. No `:spec` references remain.
- **`IRandomnessPort` and `domain.backoff` are new.** #29 (the standalone randomness port issue) becomes a prerequisite slice that the supervisor slices depend on, not a parallel effort. The pure `domain.backoff` module carries `with-jitter`, `exponential-backoff`, and a `schedule` helper — the only consumers are supervisor slices, so the module is small.
- **SIGINT handling is new.** A small shutdown hook (or `Runtime/addShutdownHook`) signals the peer supervisor to stop cleanly. The supervisor's stop fn closes `events-ch`, waits for workers to drain or hits a hard timeout, persists the final Download state, then returns. Without this, JVM-default SIGINT kills the worker mid-piece-write and loses everything since the last save. Periodic persistence remains out of scope (file a follow-up issue).
- **Per-connection budget values are deferred.** Concrete values for `N` (restarts per connection) and `T` (window in seconds) belong in the implementation slice, not this ADR. The shapes — sliding window via prune timer, address-keyed in-memory map, fresh budget per handshake attempt — are pinned here.
- **Test seams grow.** The peer supervisor is testable by injecting a fake `INetworkPort` and observing the restart-or-drop decision per address. The download supervisor is testable by driving `events-ch` directly. The intensity budget is asserted at the boundary, not via timing.
- **Per-connection vs per-supervisor intensity budgets are separate.** Per-connection budget lives in the peer supervisor and bounds churn on a single address. Per-supervisor intensity budget lives in the download supervisor and bounds churn on the whole coordinator subtree. The download supervisor's intensity is charged on coordinator crashes, swarm exhaustion transitions, and re-announce failures — *not* on every peer restart (those stay at the peer layer).
- **Crash detection is the port-envelope boundary.** Clean exits are `INetworkPort` envelope `:error` returns; crashes are anything else (`ClassCastException`, spec failures, NPE on a malformed message). Both surface as done-chan closes; the supervisor logs them differently but budgets them identically.
